# Couple Administrators to a protected USSTM Club

Administrators need Club Access to USSTM itself, not just to associated Clubs, so the Members UI can show a complete authority picture instead of a hidden `Administrator` flag with no visible scope. We're seeding USSTM as a single protected Club — fixed id, seeded by migration ahead of the legacy import, exempt from ADR-0011's archive-instead-of-delete lifecycle because it can be neither archived nor deleted — and granting it automatically whenever a Member becomes an Administrator.

The coupling is one-directional and asymmetric by design: granting Administrator inserts USSTM Club Access if absent, and that chip cannot be individually removed while the Administrator grant holds, but revoking Administrator leaves USSTM Club Access in place as an ordinary grant. Deactivation (not revocation) is the only path that strips it. This was chosen over two simpler alternatives: no Club-Access row at all (rejected — it leaves "act for USSTM" undiscoverable in the same UI that shows every other grant), and full two-way coupling where revoking Administrator also revokes USSTM access (rejected — it would force deactivation on any Administrator holding no other grant, contradicting the existing every-other-grant behavior that only the *last* remaining grant deactivates a Member). USSTM access itself stays an ordinary grant for non-administrators too: any Administrator may grant it to a non-admin Member who needs to publish USSTM's own Events, since that's a subset of authority ordinary Administrators already hold over every Club's Events.

Protection is a `clubs.protected` boolean, not a name or short-name match, since short names are user-editable.
